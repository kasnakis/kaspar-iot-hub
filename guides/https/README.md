# HTTPS με δημόσιο πιστοποιητικό (Let's Encrypt)

Ισχύει για KasPar-IoT **1.6.0** και νεότερες, εγκατάσταση με **Docker**. Ο διαχειριστής της πλατφόρμας ενεργοποιεί
ένα δωρεάν πιστοποιητικό **Let's Encrypt** για το όνομα της εγκατάστασης· η πλατφόρμα το ανανεώνει μόνη της.

**Γιατί:** με το πιστοποιητικό της ιδιωτικής CA της εγκατάστασης, κάθε browser ή κινητό θέλει πρώτα εισαγωγή της CA,
και servers που δεν ελέγχετε (ThingsBoard PE / Cloud, ChirpStack συνεργατών, webhooks όπως του 1NCE OS) δεν τη
δέχονται καθόλου. Το δημόσιο πιστοποιητικό το εμπιστεύονται όλοι.

**Τι αλλάζει και τι όχι:**
- Μπαίνει **μόνο** στο HTTPS της εφαρμογής (θύρα `WEB_TLS_PORT`, π.χ. 18443).
- Ο broker MQTT/TLS **μένει** στην ιδιωτική CA: οι συσκευές ESP32 κρατούν το `ca_cert.h` τους.
- Οι συσκευές HTTP και οι integrations στο ίδιο δίκτυο μένουν στη θύρα web (π.χ. 18080), που δεν χρειάζεται να βγει
  στο internet.

## 1. Προϋποθέσεις

| | Τι χρειάζεται | Έλεγχος |
|---|---|---|
| Όνομα DNS | Ένα όνομα (π.χ. `kaspar.example.org`) με εγγραφή **A** στη δημόσια IP του γραφείου | `Resolve-DnsName kaspar.example.org -Type A -Server 1.1.1.1` |
| Δημόσια IP | Σταθερή ή DDNS, **όχι CGNAT** (όχι `100.64.x.x`–`100.127.x.x`) | Η WAN IP του router ίδια με αυτή του DNS |
| HTTPS | `kaspar-iot https` ενεργό | Η εφαρμογή ανοίγει στο `https://<IP>:<θύρα HTTPS>` |
| Θύρα HTTPS προς τα έξω | Προώθηση της θύρας HTTPS στον router | Από κινητό με δεδομένα: `https://<δημόσια IP>:<θύρα HTTPS>` |

Το Let's Encrypt δίνει πιστοποιητικά μόνο για **ονόματα**, όχι για IP. Μετά την ενεργοποίηση, ThingsBoard, ChirpStack και
browsers πρέπει να χρησιμοποιούν το όνομα.

## 2. Η θύρα 80 για τον έλεγχο του Let's Encrypt

Το Let's Encrypt ελέγχει ότι το όνομα είναι δικό σας ζητώντας ένα αρχείο από το `http://<όνομα>/.well-known/acme-challenge/`
(μέθοδος HTTP-01, πάντα στη **θύρα 80**).

1. Στον υπολογιστή του Docker, από τον φάκελο της εγκατάστασης:

   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File .\kaspar-iot.ps1 acme
   ```

   Linux: `./kaspar-iot.sh acme`. Στην ερώτηση πατήστε Enter για τη θύρα 80 (ή γράψτε άλλη, αν ο router προωθεί το 80
   σε άλλη θύρα). Δεν χρειάζεται Administrator.
2. **Router:** προώθηση TCP **80** της δημόσιας IP → αυτός ο υπολογιστής, θύρα του βήματος 1.
3. **Windows Firewall** (PowerShell ως Administrator):

   ```
   New-NetFirewallRule -DisplayName "KasPar-IoT ACME 80" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow
   ```

Η θύρα 80 σερβίρει **μόνο** τα αρχεία του ελέγχου· οτιδήποτε άλλο ανακατευθύνεται στο HTTPS. Δεν ανοίγει την εφαρμογή,
το API ή τη σύνδεση στο HTTP.

Το `kaspar-iot health` στο τέλος πρέπει να δείξει `OK web acme -> https`.

## 3. Ενεργοποίηση από την εφαρμογή

Διαχείριση πλατφόρμας → **Πιστοποιητικά** → κάρτα **«Δημόσιο πιστοποιητικό (Let's Encrypt)»** (μόνο ο διαχειριστής
πλατφόρμας):

1. **Δημόσια ονόματα:** το όνομα του βήματος 1 (έως 10, χωρισμένα με κόμμα).
2. **Email για το Let's Encrypt:** για ειδοποιήσεις του λογαριασμού.
3. **Αυτόματη ανανέωση** (προεπιλογή ενεργή) και **Αποδέχομαι τους όρους του Let's Encrypt** → **Αποθήκευση ρυθμίσεων**.
4. **Δοκιμή (staging):** όλη η διαδρομή με τον server δοκιμών του Let's Encrypt, **χωρίς** να εγκατασταθεί τίποτα και
   χωρίς να μετρήσει στα όρια. Πρέπει να γράψει «η δοκιμή πέτυχε».
5. **Έκδοση και ενεργοποίηση.** Σε λιγότερο από ένα λεπτό το web σερβίρει το νέο πιστοποιητικό. Αν δεν το σερβίρει,
   επανέρχεται αυτόματα το προηγούμενο.

| Κουμπί | Τι κάνει |
|---|---|
| Δοκιμή (staging) | Έλεγχος όλης της διαδρομής, χωρίς εγκατάσταση |
| Έκδοση / Ανανέωση τώρα | Νέο πιστοποιητικό· όταν απομένουν ≥ 30 ημέρες χρειάζεται «αναγκαστικά» |
| Επαναφορά δημόσιου | Το αποθηκευμένο δημόσιο ξανά στο web, χωρίς Let's Encrypt |
| Απενεργοποίηση | Το web ξανά στο πιστοποιητικό της ιδιωτικής CA |

Το Let's Encrypt επιτρέπει περίπου **5** πιστοποιητικά την εβδομάδα για τα ίδια ονόματα· γι' αυτό η δοκιμή γίνεται πρώτα
με staging και το «αναγκαστικά» χρησιμοποιείται μόνο όταν χρειάζεται.

## 4. Ανανέωση

- Αυτόματη, όταν απομένουν **λιγότερες από 30 ημέρες** (τα πιστοποιητικά του Let's Encrypt ισχύουν 90 ημέρες). Δεν
  χρειάζεται συνδεδεμένος χρήστης στα Windows· χρειάζεται μόνο να τρέχει η στοίβα και να είναι ανοιχτή η θύρα 80.
- Το πολύ μία αυτόματη προσπάθεια ανά 12 ώρες. Κάθε προσπάθεια φαίνεται στο **Ιστορικό αιτημάτων** της σελίδας.
- Αν στις 14 ημέρες δεν έχει ανανεωθεί, η σελίδα δείχνει προειδοποίηση.
- Η «Έκδοση νέων πιστοποιητικών» της ιδιωτικής CA (π.χ. νέα διεύθυνση για τον broker) **δεν** αντικαθιστά το δημόσιο
  πιστοποιητικό του web.

## 5. Μετά την ενεργοποίηση

- **Browsers / κινητά:** `https://<όνομα>:<θύρα HTTPS>` χωρίς προειδοποίηση και χωρίς εισαγωγή της CA.
- **ThingsBoard:** η σελίδα Συσκευές → ThingsBoard δίνει τη διεύθυνση «από το internet» και **Credentials: Anonymous**
  ([οδηγός ThingsBoard](../thingsboard/README.md), ενότητα 3).
- **ChirpStack συνεργάτη μέσω internet:** η διεύθυνση «από το internet» της σελίδας LoRaWAN, χωρίς εισαγωγή της CA.
- **ESP32 (MQTT/TLS):** καμία αλλαγή.

## 6. Αν κάτι δεν πάει καλά

| Μήνυμα στο ιστορικό | Αιτία | Τι κάνετε |
|---|---|---|
| `connection` / `Timeout during connect` | Το Let's Encrypt δεν φτάνει στη θύρα 80 | Προώθηση TCP 80 στον router, κανόνας firewall, `kaspar-iot acme` |
| `dns` / `NXDOMAIN` | Το όνομα δεν υπάρχει ή δεν δείχνει στη δημόσια IP | Εγγραφή A στον πάροχο του domain· έλεγχος με `-Server 1.1.1.1` |
| `unauthorized` | Η θύρα 80 απαντά, αλλά από άλλον server | Η προώθηση δείχνει σε λάθος υπολογιστή ή άλλο web server στη θύρα 80 |
| `rateLimited` | Πολλά πιστοποιητικά για τα ίδια ονόματα | Περιμένετε· χρησιμοποιήστε τη δοκιμή (staging) |
| «Η θύρα του Let's Encrypt είναι κλειστή» | Δεν έχει τρέξει το `kaspar-iot acme` | Βήμα 2 |
| «port 80 is already in use» | Κάτι άλλο κρατά τη θύρα 80 (IIS, άλλος web server, παλιό certbot) | Σταματήστε το ή διαλέξτε άλλη θύρα με προώθηση 80 → αυτή στον router |

**Μέσα στο γραφείο** το όνομα μπορεί να μην ανοίγει, αν ο router δεν κάνει *NAT loopback*. Τότε χρησιμοποιήστε μέσα στο
δίκτυο την τοπική IP, ή ένα τοπικό DNS που δίνει την τοπική IP για το όνομα. Αποφύγετε μια γραμμή στο αρχείο `hosts`
ενός φορητού: εκτός γραφείου το όνομα δεν θα ανοίγει.

## Ασφάλεια

- Ανοίγουν προς τα έξω μόνο η θύρα HTTPS και η θύρα 80 του ελέγχου. Η θύρα HTTP των συσκευών (π.χ. 18080) μένει στο
  τοπικό δίκτυο.
- Το κλειδί του πιστοποιητικού και το κλειδί του λογαριασμού Let's Encrypt μένουν στον τόμο `kaspar-iot-webtls` και τα
  διαβάζει μόνο η υπηρεσία `pki`. Η εφαρμογή γράφει μόνο το αίτημα.
- Κάθε ενέργεια στο δημόσιο πιστοποιητικό γράφεται στο αρχείο ενεργειών (`certificate.public.*`).
